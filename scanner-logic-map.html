Source of every technical signal — squeeze, Bollinger/Keltner, RSI, MACD, moving averages, relative strength. Pulled from Polygon. Fresh to prior close.

Gamma flip, call/put walls, γ-ratio — the positioning half. Our own compute via the gex-levels edge function + _shared/gex_math.ts. Covers ~61% of names (894/1463).

The rubric · DATA
The 17 conditions
public.scanner_conditions (key, kind, points, threshold, enabled)
This is the config layer. One row per condition — gate / score / kill — with its points, threshold, and on/off flag. The grader reads it live every run, so editing this table changes the scan. This is what a config UI edits.
EDIT HERE = tune the rubric (points, thresholds, enable)
↓
The grader · LOGIC
The scoring engine
public.scanner_squeeze_daily() — SQL function
Reads bars + GEX + the 17 conditions, gates on squeeze, evaluates each enabled condition, sums points, applies kills (cap at D), writes the graded scoresheet. Confirmed it uses enabled, points, threshold, and kind from the table. The math for each signal lives here — a brand-new indicator gets added in this function.
EDIT HERE = add a NEW signal's math
↓
Scheduler
The daily refresh
cron: scanner-squeeze-refresh-daily → public.scanner_squeeze_refresh()
Runs 8:20 AM CT, Mon–Fri (13:20 UTC). Promotes the freshly graded day into the results table the page reads.
change here = run time / cadence

One row per ticker per day: grade, score, points earned, kills, and the full per-condition breakdown JSONB. ~1,463 tickers, snapshotted daily (history back to 2026-07-02).

Screen
The scanner page
scanner.html (472 lines — renderer only)
Reads the results view and draws the tiers, grades, and the scoresheet slide-out. Holds no logic — purely presentation. Changing a threshold here does nothing; the logic is upstream.
change here = look & layout only
The one thing to remember: the logic is not in the HTML. Tuning the rubric is a data edit to scanner_conditions (safe, live, no code). Adding a genuinely new signal is a one-time edit to the scanner_squeeze_daily() function, after which it becomes another row you can tune. Everything else — bars, GEX, the cron, the results table — is plumbing that feeds those two.
