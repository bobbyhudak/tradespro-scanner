How it grades: a name must first pass the gate (be in a squeeze) to appear. It then earns points across the 13 score conditions — 15 points possible (8 technical + 4 positioning + 1 sector). The three kill conditions override the score and cap the grade at D no matter how many points were earned. Score percent = points earned ÷ points possible → letter grade.

Why this matters for "configurable": every number on this page — points, thresholds, enabled — already lives in public.scanner_conditions, one row per condition. The scan reads the table each run. A config UI is a thin editor over these 17 rows, not a rewrite of the scanner.
